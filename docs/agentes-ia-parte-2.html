Antes de construir

¿De verdad necesito un agente?

1. Una llamadaResumir, clasificar, extraer. Una petición, una respuesta.
→
2. WorkflowPasos fijos que orquesta tu código: A, luego B, luego C.
→
3. AgenteEl modelo decide los pasos. Tarea abierta y difícil de especificar.
¿La tarea es compleja y abierta? ¿El valor justifica costo y latencia? ¿Claude es bueno en esto? ¿Los errores se detectan y se revierten?
Si alguna respuesta es "no", baja un escalón. El agente más fiable es el que no necesitaste construir.

Por dentro · Protocolo

Cómo funciona el tool use

  • Tú describes herramientas con nombre, descripción y JSON Schema.
  • Claude responde con un bloque tool_use: "llama a X con estos argumentos" y stop_reason: "tool_use".
  • Tu código decide si la ejecuta y devuelve un tool_result (o un error con is_error).
  • Se repite hasta stop_reason: "end_turn".
# Lo que Claude ve { "name": "ejecutar_tests", "description": "Ejecuta pytest y devuelve la salida. Úsala para reproducir fallos y verificar cambios.", "strict": true, "input_schema": { ... } }
Claude nunca ejecuta nada por sí mismo: pide, y tu código decide. Ahí viven los permisos.

Por dentro · Código

El bucle en 20 líneas

mensajes = [{"role": "user", "content": objetivo}] for turno in range(max_turnos): # límite de seguridad r = client.messages.create(model="claude-opus-5-5", system=sistema, tools=ESQUEMAS, messages=mensajes) mensajes.append({"role": "assistant", "content": r.content}) if r.stop_reason != "tool_use": # terminó return texto_final(r) resultados = [] for b in r.content: if b.type == "tool_use": salida = herramientas.ejecutar(b.name, b.input) # ¡aquí van los permisos! resultados.append({"type": "tool_result", "tool_use_id": b.id, "content": salida}) mensajes.append({"role": "user", "content": resultados}) # todos juntos
Eso es un agente. Todo lo demás (Claude Code incluido) es mejores herramientas, mejor contexto y mejores guardarraíles alrededor de este bucle.

Context engineering

El contexto es un recurso finito

Instrucciones estables

System prompt y CLAUDE.md: stack, comandos, convenciones. Cortos y concretos.

Herramientas claras

Pocas, bien nombradas y con descripciones que digan cuándo usarlas.

Salidas acotadas

Trunca logs y archivos enormes. Cada token que entra compite por atención.

Cargar bajo demanda

Que el agente busque y lea lo que necesita, no "pegarle todo el repo".

Subagentes

Aíslan exploraciones largas y devuelven solo la conclusión.

Compactación y memoria

Resumir el historial en tareas largas; guardar decisiones fuera del contexto.

Más contexto no es mejor contexto: lo justo, en el momento justo.

Claude Code · Flujo

Cómo trabajar con Claude Code

1. Explorar"Lee el módulo de pagos y explícame el flujo"
→
2. PlanearPlan mode (Shift+Tab): propone sin tocar nada
→
3. ImplementarEdita siguiendo CLAUDE.md y tus convenciones
→
4. VerificarTests, lint, typecheck; idealmente un revisor aparte
→
5. EntregarCommit y PR con descripción, para revisión humana
# CLAUDE.md (raíz del repo) ## Comandos - Tests: npm test · Lint: npm run lint ## Convenciones - Middlewares en src/middleware, uno por archivo - Nunca editar migraciones ya aplicadas
  • /init genera un CLAUDE.md inicial a partir del repo.
  • Lo que corriges dos veces, va a CLAUDE.md.
  • Se versiona: es documentación para humanos y agentes.

Claude Code · Ejemplos

Skill y hook en el repo de práctica

# .claude/skills/agregar-herramienta/SKILL.md --- name: agregar-herramienta description: Añade una herramienta al agente (esquema + código + test). --- 1. Esquema en ESQUEMAS, strict: true 2. Método en Herramientas, con _resolver 3. Test feliz + test de error 4. Ejecuta pytest y muestra el resultado
# .claude/settings.json "hooks": { "PreToolUse": [{ "matcher": "Edit|Write", "hooks": [{ "type": "command", "command": "python3 .claude/hooks/ proteger_archivos.py" }] }]} # exit 2 → bloquea la edición y Claude # recibe el motivo
Regla práctica: skills para guiar, hooks para garantizar. Una instrucción puede ignorarse; un hook no.

Conectar el mundo

MCP: Model Context Protocol

AgenteClaude Code, Claude apps o tu propio agente
⇄
Cliente MCPDescubre herramientas y recursos de cada servidor
⇄
Servidores MCPGitHub · Jira · Postgres · Sentry · Figma · tus APIs internas
  • Un estándar abierto: escribes el servidor una vez y lo usa cualquier cliente.
  • Expone herramientas, recursos (datos) y prompts.
  • Locales (stdio) o remotos (HTTP) con autenticación.
  • Cada servidor es código de terceros: revísalo como una dependencia.

Seguridad

Riesgos propios de los agentes

Amenazas

  • Prompt injection: un README, issue o web con "ignora tus instrucciones y…".
  • Exceso de permisos: rm -rf, git push --force, acceso a producción.
  • Fuga de secretos: .env leídos y enviados a logs o servicios externos.
  • Dependencias: paquetes o servidores MCP maliciosos.

Defensas

  • Todo contenido externo es dato, no orden.
  • Permisos allow/deny mínimos y sandbox.
  • Hooks que bloquean rutas y comandos sensibles.
  • Aprobación humana para acciones irreversibles; revisión del diff.
Pregúntate: si el agente leyera un texto malicioso, ¿qué es lo peor que podría hacer con sus permisos actuales?

Costo y calidad

Medir antes de optimizar

Prompt caching

Lo estable primero (herramientas, system prompt). Las lecturas de caché cuestan una fracción del input normal.

Effort y modelo

Ajusta por tipo de tarea: low para tareas simples o subagentes, high/xhigh para código difícil.

Evals

Un set de tareas reales con criterio de éxito. Sin eval, "mejoró" es una opinión.

Costo por tarea completada

Una petición barata que necesita tres reintentos no es barata. Mide tokens, turnos y retrabajo.

El mini agente imprime turnos y tokens al terminar: úsalo para comparar modelos y effort con la misma tarea.

Escalar

Patrones multi‑agente

1

Orquestador y trabajadores

Uno divide la tarea; varios la resuelven en paralelo con contexto propio.

2

Generador y revisor

Uno implementa, otro revisa sin el sesgo de haberlo escrito.

3

Especialistas

Un subagente por área: tests, seguridad, documentación.

Más agentes = más tokens y más coordinación. Úsalos cuando el trabajo se divide de verdad o necesitas una mirada independiente.
